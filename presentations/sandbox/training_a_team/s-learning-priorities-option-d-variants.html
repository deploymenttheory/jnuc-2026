Slide 9 - Learning priorities by role (Option D variants)

Follow-on from the five-option round in s-learning-priorities-role-clarity (PR #7): Joseph liked Option D, the role-by-org-size matrix, but wants it to fill more of the page, and three genuinely different ways to present the same argument - one as a literal table, one as a drawn graphic, one as prose. All three keep Option D's core idea (the minimum bar per role is fixed; what changes with org size is what the team owns underneath it) and all three keep both points the speaker wants landed - each role only needs a minimum, not everything, and what the team owns and how steep the climb is scales with org size - along with every settled fact from AGENTS.md's "How #9's two charts are scored": Jamf APIs score identically in both org sizes, Environment is the real differentiator, Git and GitOps barely move (the loss is authority, not knowledge - a second approver, narrower GitHub access, Checkov and the linters staying on), and Mentoring runs low in a small org and high in a large one. Each is built as real markup inside #s-learning-priorities (.s-learning-priorities-optd-table, -optd-graphic, -optd-text), sized noticeably bigger than the original Option D grid. The deck still ships -opt-a by default; this page's CSS just flips which wrapper is visible per iframe. Compare the current slide.

Option A - Table

A literal, ruled <table>: a header row (Role / Minimum to do the job / Small org / Large org), one row per role with hairlines between, and a footer row stating the Jamf APIs fact once across the full width. Reads like a reference table someone could look back at rather than a card grid dressed up to resemble one. Bigger type and more generous row padding than the original Option D grid make it fill most of the page. Pick this if the room wants a lookup they can scan role by role.

Option B - Graphic

    
A genuinely drawn treatment. Three identical pill shapes for junior, engineer and senior carry point one on their own - same size regardless of org, because the minimum does not move. Underneath, an inline SVG chart draws one scaled bar per discipline (Environment, Git & GitOps, Jamf APIs, Mentoring), small org against large org side by side: bar length is the argument, not the words in a cell. Environment's bar shrinks hard from small to large org, Jamf APIs' bar is drawn identically in both (same length, same colour, to make "no difference" visible rather than stated), Git & GitOps keeps the same length in both but changes colour to signal authority narrowing rather than knowledge shrinking, and Mentoring's bar grows. A one-line caption under each row still carries the exact fact in words. Pick this if the room responds better to a shape than a sentence.

Option C - Text

    
A text-led treatment close to how migrating_an_instance's plainest slides read: large type, short lines, almost no grid or ruling. One large opening statement for each point, and one flowing paragraph per role that pairs its fixed minimum with what changes underneath it by org size in a single sentence, rather than splitting the two into separate cells or columns. No SVG, no table, no cards - the argument is entirely carried by sentence structure and type scale. Pick this if the slide should read as an argument being made rather than a reference being consulted.
