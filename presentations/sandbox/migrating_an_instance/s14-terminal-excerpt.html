Slide 15 - the terminal excerpt

The block at the top of the slide is meant to read as an excerpt from a terminal, and at the moment it does not: it sits on the same navy card surface as the four gate cards below it, its three dots are border-grey and easy to miss, it carries no window title, and the command and its output are set at the same weight. Nothing about the wording or the four gates changes in any option, and nothing in the deck changes in this PR - the options below are three treatments of that block alone. Each render is the real #s14 slide with one option's CSS on top, plus the small piece of markup that option needs (a window title, a cursor, a tab label), injected the same way.

ABCD

Option A - the block as it stands live now

The deck as it ships today, for comparison. A centred 1240px card with a thin head bar, three grey dots and a monospace body: the command in muted cornflower, a blank line, then the result in lime. It is a card that happens to contain monospace text, which is the whole of Joseph's point - it is the same fill, the same border and the same corner radius as the four gate cards a few hundred pixels below, so nothing signals that one is a machine talking and the others are a person writing. Pick this only if the block is fine as a code sample and the terminal framing is not worth the extra chrome.

Option B - a real window

    
The block becomes a window sitting on the stage rather than a card lying flat on it. The head bar takes a light grey fill so it reads as window chrome instead of a card header, the three dots become actual traffic lights in the deck's red, amber and lime, and a centred monospace title, joseph@jnuc - zsh, names what the window is. Under the chrome the command is set in white and bold - what a person typed - against the lime result underneath, and a lime block cursor blinks on a fresh prompt line below the output, which is the single strongest cue that this is a live shell and not a static sample. A drop shadow lifts the whole thing off the blue. The four gate cards are untouched, so the separation comes entirely from the window chrome. This is the smallest change of the three and the one that survives being seen from the back of a room; pick it if the block should look like a screenshot someone took. In the deck it needs one span added inside .term-head for the title and a cursor span at the end of .term-body.

Option C - a console dump, no chrome at all

    
The opposite move: strip the window furniture rather than add more of it. The head bar and its dots are gone, the card loses its border and its rounded corners, and the block runs the full width of the slide with a heavy lime rule down its left edge, the way a quoted console dump is set in documentation. The type steps up from 26px to 44px so the command and the result carry the top third of the slide on their own, the command in white and the result in lime, with a solid lime block cursor waiting on the next prompt. To pay for that weight the four gate cards give up their fills, borders and corners and become four bare columns under hairline rules, gate 4 keeping its red rule - so the slide has exactly one solid object on it and the eye has nowhere else to go. Pick this if the zero-diff result is the point of the slide and the gates are the supporting detail. In the deck it needs a cursor span at the end of .term-body and nothing else.

Option D - a quoted excerpt

    
The block is labelled rather than dressed up. A lime tab reading "Terminal" sits on the top-left corner of the block, the way a code sample is labelled with its language, and the block below it is inset behind an 8px lime rule with square corners on that side. The surface is not the flat card navy any more: a gradient lightens the top of the block and faint scanlines run down it, so it reads as a screen being quoted rather than a panel. Inside, the hierarchy is inverted against the other options - the command drops to caption size in muted cornflower, because nobody needs to read it twice, and the result is promoted to 44px bold with a lime tick in front of it, which is the sentence the slide exists to show. The gate cards stay as cards but lose their fill and take smaller, muted numbers, so they sit clearly below the excerpt rather than beside it. Pick this if "No changes" is the line you want people to remember. In the deck it needs a tab element before the terminal card and a tick span at the start of .term-ok.
