Slide 14 - for_each exceptions, policies only

Dock items were never an exception, so the dock items card is gone from every option, and the reason for the policies exception is reworded from payload complexity and readability to how diverse policies are. Both of those are already in this PR's deck, so they are identical across A to D; what differs is how a slide covering a single exception fills its space and makes the diversity argument. All four markup wrappers ship inside the real #s13 section; each render below is that same slide with one CSS rule on top choosing which wrapper shows. Accepting an option means deleting the other three wrappers and their CSS as one block.

ABCD

Option A - one exception, one panel live now

The removal done cleanly. The two-card grid was half the slide, so taking the dock items card out would have left an obvious hole; instead the remaining exception becomes one full-width panel split into a name column and a reason column, divided by a hairline. The name column holds "Policies" in large lime monospace with a "plain HCL" tag under it, so the exception itself is the first thing read; the reason column leads with "Too diverse to share one shape." and then explains it in one sentence, which is where the payload-complexity wording used to be. The lead now names policies as the one resource type left in plain HCL, and the closing line about the map costing more than it pays for is unchanged. Pick this if the slide should stay a plain statement of fact in the deck's existing idiom - it is the least risky of the four and the only one that needs no further decisions.

Option B - the diversity drawn

    
The argument made by picture rather than by sentence. Five policy silhouettes stand in a row, each a stack of cornflower blocks with different heights, different indents and a different number of them, so at a glance no two policies are the same shape - one is a single slab, one is five nested pieces. A sixth column stands at the end in dashed lime outline: the union of all five, everything a shared map would have to carry, drawn deliberately taller than its column so it runs off the bottom edge and does not fit. The caption under it says "One map" rather than "Policy". The blocks are abstract on purpose, because which policy payloads actually vary is not recorded anywhere - there is a TODO chip on the closing line for that. Pick this if the point worth landing is that the diversity is real and visible, not just claimed.

Option C - the map attempt against the plain HCL

    
Two HCL panels side by side, and not as equals. The left is the for_each map as it would have to be written for policies - each.value, lookup with defaults, a dynamic block for scope and another for payloads - carried at reduced strength in the narrower column with a red "dropped" tag. The right is the same policy written straight out, in the wider column, at full strength, with a lime "kept" tag and a lime edge on the code panel. The verdict is legible before a word of the code is read, and the code then backs it up: the map is mostly plumbing, the plain version is shorter and says what it does. Slide 13 has just shown a for_each comparison that the map won, so this reads as the same test run again with the opposite result. Both samples are plausible jamfpro_policy HCL with a TODO chip against the field names until they are checked against the provider schema. Pick this for the audience that wants to see the thing rather than be told about it.

Option D - the statement on its own

    
Almost nothing on the slide. A small lime kicker, "One exception", sitting on a lime rule; under it the statement at hero size, "Policies stayed in plain HCL", with the last two words in lime; under that the reason in one sentence at heading size; and one muted supporting line at the bottom, the existing closing line about the map costing more than it pays for. No cards, no code, no diagram. The slide takes ten seconds and the detail lives in the speaker's mouth rather than on the wall, which suits a slide that exists to be honest about a limit rather than to teach anything. Pick this if the deck is running long by this point, or if the exception should register as an aside between two heavier slides.
